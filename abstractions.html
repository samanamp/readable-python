Chapter 09 of 11

Abstractions

Build for the load you have.

RP13

Add an abstraction at the second implementation, not the first.

With one implementation you can't know which parts will vary, so the interface you design is a guess, and every reader pays for it. With two real cases, the right seam is usually obvious.

The speculative framework

A common shape in young codebases: an abstract base class, a plugin registry, a two-level contract ("implement these five methods, or optionally this sixth one to replace the loop"), a generic batching layer, three execution lanes… and one implementation, running at batch size one.

Each piece might be reasonable on its own. Together they mean a newcomer reads five files and three interfaces to find the 40 lines that actually run. Worse, when the second real use case arrives, it rarely fits the interface designed for an imagined one.

When a second selection policy really shows up, extract the interface then, shaped by both real cases. It takes ten minutes.

Guidelines

Earn generality with numbers

Batching, caching, pooling and pipelining are abstractions over performance. Add them when a measurement shows the need, for a specific model or workload, and keep the measurement in the PR (chapter 8).

Prefer composition of plain functions to class hierarchies

Inheritance deeper than one level makes the reader hunt through files to find which method actually runs. A function that takes a callable, or a class that holds another object, is easier to follow.

Protocols at real seams only

A typing.Protocol is great at a boundary with several genuine implementations (several model backends, a real and a fake transport for tests). A protocol with one implementation is a second copy of that class's signature to keep in sync.

Delete unused paths

Configuration flags nobody sets, fallback implementations nobody runs and compatibility shims for callers that are gone should all be deleted. Unused code still has readers.

A thin wrapper must add something

A class that only forwards calls to another class, or a function that only renames another function, is indirection without value. Call the real thing.
