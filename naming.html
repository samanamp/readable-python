Naming

Names from the domain, used consistently.

RP08

Name things with domain words, and use the same word for the same thing everywhere.

A codebase is a vocabulary. If "session", "conn", "client" and "stream" all mean the same thing, every reader has to learn four words for one idea, and will suspect they mean four different things.

Build a small glossary

Keep a short list of the core nouns of your system, with one-line definitions, in the README or at the top of the main module. For a serving system it might be:

WordMeansNever call it
Sessionone user's live connection to a modelclient, conn, stream, job
Requestan ask to start a session, before it's admittedsession (it isn't one yet)
Batchthe inputs stepped together in one model callcohort, group, bundle
Chunkthe output of one step for one sessionresult, frame, piece
Workera process that owns one GPUreplica, node, unit

Then hold the line in review. New words need a reason.

Guidelines

Functions are verbs, values are nouns

admit(request), next_batch(), encode(frames). Booleans read as questions: is_running, has_capacity, can_accept().

Say what it is, not what type it is

Units in the name when they aren't obvious

timeout_s, bitrate_kbps, latency_ms, size_bytes. This prevents a whole class of bugs that types don't catch.

Length matches scope

A loop index over three lines can be i. A module-level constant read in five files needs a full name. Avoid abbreviations except universal ones (id, url, gpu, fps).

Private means private

A leading underscore says "not part of this module's interface". Use it for that, and don't import _names from other modules. If another module needs it, it's public; drop the underscore.

No framework words for domain things

Manager, Handler, Processor and Helper say almost nothing. Prefer what the thing actually does: Scheduler, WeightsCache, FrameEncoder.
