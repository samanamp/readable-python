4Functions

Small, one level of abstraction, results instead of side effects.

Rule 6. Functions return results. They don't mutate their arguments. A caller reading x = f(a, b) assumes a and b are unchanged. When they aren't, every call site becomes a trap.
Rule 7. One level of abstraction per function, and at most four parameters. A function that mixes "decide what to do" with "flip these bits" makes the reader zoom in and out on every line. More than four parameters usually means a missing object.

Hidden mutation

A free function that takes the caller's containers and fills them in is the most common way readable code turns unreadable.

The method changes state too, but it changes its own state, which is what a reader expects from self.join(...). The rule is about surprise: mutate yourself, never your arguments.

Guidelines

Command or query, not both

A function either answers a question (next_batch(), can_accept()) or does something (join(), flush()). Avoid functions that do something and return an unrelated answer. Returning whether the action succeeded is fine.

Return early, keep the happy path flat

def admit(self, request: Request) -> Session | None:
    if request.model != self.model_name:
        return None
    if len(self.sessions) >= self.capacity:
        return None
    session = Session(request.id, request.context)
    self.sessions[session.id] = session
    return session

Keyword-only for anything ambiguous

resize(img, 512, 512, True) tells the reader nothing. resize(img, width=512, height=512, keep_aspect=True) does. Use * to force keywords for booleans and anything after the first two arguments.

No closures defined inside long functions

A helper defined halfway through a 100-line function captures variables from around it, and the reader has to work out which. Make it a method or a module-level function with explicit parameters.

Type-annotate signatures

Annotate every public function's parameters and return value. It's the cheapest documentation there is, and it stays correct because the type checker reads it too. Inside function bodies, annotate only where it helps the reader.
