Most hard-to-follow code is hard because of state: who can change this value, and what else has to change with it? Make that answer short.

Rule 4. Every piece of state has exactly one owner. If two places can change a value, every reader has to check both. If a value must change together with another, they belong in the same object.
Rule 5. Use an enum for status, not a pile of booleans. Three booleans allow eight combinations, most of them nonsense. An enum lists the states that can actually happen.

Parallel containers

A classic smell: several dicts keyed by the same id, which every code path must update together.

Adding a field to Sequence can't create a leak, because removal is one line that removes everything.

Status as an enum

If transitions matter, put them in one method (def transition(self, to: WorkerState)) that rejects illegal moves. Then the full state machine is in one place.

Guidelines

Owners are objects, not modules

Module-level mutable globals have every function in the module as a potential writer. Put the state on an instance and pass the instance in.

Prefer immutable messages

Anything that crosses a boundary (a request on a queue, a batch handed to the model, a result coming back) should be a @dataclass(frozen=True) or a plain value. Then the receiver can't accidentally change the sender's copy, and you never need a defensive deep copy.

Derive, don't store

If a value can be computed from other state cheaply (len(self.running), "is the batch full?"), compute it. Every stored copy is another thing to keep in sync.

Make invalid states unrepresentable

If a sequence only has a finish_reason once it's finished, consider a separate FinishedSequence type, or an Optional that's checked in exactly one place, rather than a field that's "usually set".
